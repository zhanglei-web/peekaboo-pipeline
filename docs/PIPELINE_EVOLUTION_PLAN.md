# 无 rosbag 中转与双 Qwen 流水线实施计划

日期：2026-11-05。状态：原设计与实施计划。`11-5`分支已加入独立实现，实际入口、验收证据、部署调整和限制见[11-5文档](PIPELINE_11_5.md)。本文保留设计边界，不能据此宣称完整双接口联调已经通过。

本次修订重点：依据本机实际硬件和历史模型日志，补充CPU/GPU阶段拆分、端点与算力映射、本地模型驻留管理、GPU互斥及验收。API数量不等于可以同时运行的GPU任务数量。

## 1. 目标与实施边界

目标：预处理后的图像及元数据直接供 Astra 使用，取消标注链路中的 rosbag 写入、读回、再提取；一个 Astra 服务准备任务，两个独立 Qwen API在资源允许时并行处理不同数据。保留当前最终 JSON 的内容范围、空间树、时序关系和证据关联。本机已有Qwen部署单独列入资源拓扑，在端点核验前不能自动认定它是两个API之一，或是可以额外并行使用的第三个服务。

第一版以一条 episode 为阶段交接单位。不同 episode 可以处在不同阶段；同一 episode 的时序空间更新保持顺序。事件描述与时序更新暂时分开，合并作为独立对照实验。

设计阶段未修改代码；后续用户已授权开发，在保留11-4标签的独立11-5分支实施。测试只使用独立验证目录，不覆盖现有29条、此前81条或已复制的数据。

相关基线：[现有输出规范](OUTPUT_SPEC.md)、[字段字典](FIELD_DICTIONARY.md)、[现有终端指南](TERMINAL_GUIDE.md)。输出规范是兼容性边界，不能为了提速删除字段、放松校验或把未知值补成确定事实。

## 2. 当前流程与目标流程

当前流程：

```text
原始视频/IMU/标定/时间戳 + 事件MD及三帧
  → 输入审计 → VIO → 运动筛帧 → 校正 → 深度
  → rosbag导出与读回 → 提取RGB/时间戳/TF/位姿
  → Astra粗筛与精筛 → Qwen场景
  → Qwen逐事件描述 → Qwen顺序更新时序空间关系
  → 组装、验证、人工确认结果投影与目标格式导出
```

目标第一版：

```text
原始输入及事件证据
  → 输入审计 → VIO/筛帧/校正/深度
  → 直接消费包 + 完成回执 → 待筛选队列
  → Astra粗筛与精筛 → 待标注队列
  ├→ Qwen服务1：episode A场景 → 事件描述 → 顺序时序更新
  └→ Qwen服务2：episode B场景 → 事件描述 → 顺序时序更新
  → 组装校验 → 最终JSON及两个目标格式
```

CPU预处理下一条、Astra准备另一条、两个Qwen标注两条可以在资源允许时重叠。图示是逻辑流程；本地深度与本地Qwen受第5节GPU互斥规则约束。两个远端Qwen具有独立算力时，才可与本地深度持续重叠。

取消 rosbag 不等于取消深度。第一版保留既有预处理范围、参数及质量诊断；深度单独保存。若未来仅保留标注所需RGB/位姿而取消深度，必须作为单独的范围变更评估。

## 3. 数据接口边界

建议引入版本化的“直接消费包”。以下名称为设计名称，不是已发布的schema。

### 3.1 episode 输入清单

- episode_id、所属数据批次、场景组、搜索目标、帧率及来源。
- 原始采集目录、视频/IMU/标定/时间戳的身份信息和哈希索引。
- 事件MD身份、每个事件ID及顺序、左右目开始/中间/结束图像路径和哈希。
- 人工事实清单的显式关联；未关联时不能自动继承其他批次的结果规律。
- 文件名帧号、解码序号和传感器时间的映射及偏差审计。

### 3.2 预处理输出清单

每个候选帧至少包含：episode_id、稳定frame_id、原视频帧号、左右解码序号、传感器时间戳、图像路径/哈希/尺寸/编码、原图或校正图标识、相机参数引用、相机参考坐标系、位姿/TF及质量状态、筛选原因、预处理版本。保留位姿协方差及原诊断的引用；不可用的几何量不得伪造默认值。

深度、置信度、单位及其对应校正图索引单独保存并引用。当前标注入口不读取深度，不应为模型传输无用的大体积深度数据。

必须区分两路图像：

1. 场景候选图：来自预处理的校正RGB，供Astra筛选。
2. 事件三帧：来自既有标记资料，保留原图、文件名帧号与证据身份。

运动筛帧和Astra筛帧都不能删除第二路事件证据，也不能拿邻近场景关键帧冒充事件三帧。两路图像坐标系不同，不能直接混用像素坐标。

### 3.3 发布与恢复

先写临时文件，校验图像可读、哈希、时间戳、左右同步、帧序和清单字段，再原子发布完成回执。下游只消费具有合法回执的不可变输入。

回执包含输入与输出哈希、参数/代码/接口版本、数量、质量状态、时间及输出位置。完成阶段后保留可恢复的磁盘缓存；队列传文件引用，不长期积压完整图像在内存。缓存清理应在消费成功后按明确保留策略执行，不能删除原始输入和必需审计证据。

取消bag后，用直接包完整性验证替代bag读回验证。它验证的是直接包，不能宣称仍完成了九个ROS topic的反序列化读回。数据完整性通过也不等于VIO几何质量通过。

### 4.1 S1拆分为CPU准备与GPU深度

S1a负责输入检查、VIO、运动筛帧和校正等当前主要在CPU执行的工作，输出校正图、帧索引和位姿诊断，状态为等待深度。S1b负责GPU深度与置信度计算，读取已完成的S1a产物，完成深度校验后才能进入S2的完整消费包发布。S1a不持有GPU任务锁；如以后改用GPU解码、校正或VIO，则必须重新声明资源需求。

第一版仍以每条完整预处理通过作为Astra交接条件，保留深度范围，不默默跳过失败深度。改变的是原先整批全部完成后才标注的全局屏障：新版本按每条合法回执放行；这需要新调度实现，现有11-4入口仍保留整批29条门槛。

标注当前不读取深度，因此未来可以另做RGB/位姿包先就绪、深度随后完成的双就绪接口。但这会改变任务完成语义，第一版不默认采用；若采用，最终整条完成仍需满足约定的深度交付条件。

S4—S6第一版由一个Qwen worker负责一条数据，保持当前场景、全部事件描述、顺序时序更新的调用关系。完成后该worker领取下一条。

若后续优化单条延迟，可以让S4与不依赖场景节点的S5描述重叠，再统一节点对齐；S6仍需等待对应依赖完成。任何API都可以处理下一事件，只要收到完整的有效状态。服务身份不代替上下文管理。

## 5. 调度、资源与失败边界

### 5.1 服务配置与队列

- 配置一个Astra端点和两个Qwen端点，各自记录模型身份、接口能力、限流、超时和并发上限。密钥只通过环境或密钥配置读取，不进入文档、Git和日志。
- 两个Qwen是否同模型、量化、思考配置、图像预算和schema约束能力，实施前核验。独立API并不自动代表独立算力或没有共享限流。
- 若两端模型或参数不同，分开记录并先验证质量；不能把不同模型结果无标识混为同一版本。第一轮对照尽量固定模型、提示词、思考开关和预算。
- 起始调度：一个Astra活动请求；每个Qwen端点一个活动请求。更高并发必须按服务限额与实测另行调整。
- 队列有容量上限，积压时暂停上游领取新任务；不能静默丢帧或丢episode。两个Qwen空闲者领取下一条，通过租约/锁避免重复消费。
- 一条空间图只允许一个有效写入者。关系变化通过前置状态版本校验后原子提交。

### 5.2 GPU资源

#### 5.2.1 本机核验依据与结论

2026-11-05检查：本机为RTX 5090 Laptop GPU，显存总量24,463 MiB；CPU有24个逻辑处理器，系统内存约62 GiB。检查时没有运行llama-server；模型已部署不代表当前正在占用显存。空载显存只是检查快照，不能作为未来同时运行的峰值依据。

本地Qwen是Qwen3.8-27B Q4_K_M，视觉投影为Q8_0，ctx_size为16,384，parallel为1，思考关闭。历史启动日志记录GPU模型缓冲17,402.38 MiB、KV缓冲1,024 MiB；二者相加已为18,426.38 MiB，尚不包括视觉、计算、驱动和其他动态占用。总显存扣除这两项仅剩约6,037 MiB。

现有深度调度的启动门槛为至少10,000 MiB空闲显存。这是现有调度门槛，不是已测得的深度峰值。即使Qwen没有活动请求，权重及缓存仍驻留，按上述配置也无法满足该门槛。不能靠把请求暂停或降低该门槛来宣称解决资源冲突。

结论：第一版将本地深度与本地Qwen模型驻留设为互斥，不计划同卡并发。不修改量化、分辨率、上下文、深度参数或CPU卸载来凑显存；这些都是需要另做质量和性能评估的变化。

#### 5.2.2 哪些阶段可以重叠

| 组合 | 第一版规则 | 限制或依据 |
|---|---|---|
| CPU预处理 + 本地Qwen | 允许有限重叠 | 监控CPU、系统可用内存、交换和磁盘；Qwen也会消耗CPU，不保证零性能影响 |
| GPU深度 + 本地Qwen驻留/推理 | 禁止同时占用本机GPU | 请求空闲不释放模型显存，必须完成受控卸载后才能切换 |
| GPU深度 + 远端Astra/Qwen请求 | 允许 | 远端确实不使用本机GPU；本地解码、打包和网络仍需限流 |
| 两个Qwen API | 经资源拓扑核验后允许 | 端点或密钥不同不能证明底层算力独立；本地同一服务parallel=1不能算两槽 |
| CPU最终组装/校验 + GPU任务 | 允许有限重叠 | 哈希与图像验证可能争用磁盘，按负载背压 |

#### 5.2.3 部署模式与推荐

| 模式 | 任务分工 | 调度策略 |
|---|---|---|
| R：两个Qwen均在远端 | 本机CPU预处理、本机GPU深度；Astra及双Qwen远端推理 | 优先选择的持续流水模式；本地Qwen不自动启动 |
| H：一个Qwen本地、一个远端 | 远端持续工作；本机GPU轮换深度和本地Qwen | GPU按一组episode切换，避免每事件装卸模型；不承诺两个Qwen持续满载 |
| L：全部Qwen实际依赖本机同一GPU | 深度与本地推理分时 | 保持阶段或分组运行，不能宣称真正双Qwen并行；现有parallel=1维持单请求 |
| X：两远端之外还有本地Qwen | 本地作为可选第三推理资源 | 第一版不自动启用；只有无深度等待、资源和模型质量均核验后另评估收益 |

本机已有模型不要求流水线一定使用它。若两个独立Qwen API都在远端，推荐使用R模式，把本地GPU留给深度。端点位置未核实前，按可能共享资源保守调度，不启动第三个worker。

#### 5.2.4 单GPU互斥、交接与公平性

GPU互斥需覆盖模型整个驻留生命周期，而非仅覆盖一次HTTP请求。逻辑状态为：空闲 → 深度占用 → 清理释放 → 空闲，或空闲 → 本地Qwen加载/驻留 → 停止接单/排空请求 → 卸载释放 → 空闲。清理失败时资源仍标记占用，不能直接授予另一方。

由一个资源管理器维护所有者、PID/create_time/命令、租约和心跳；获取互斥权后还需检查实际显存及活动进程。租约过期不能自动证明GPU已释放，必须核实原进程和服务状态。队列、超时或锁文件单独存在都不足以判断资源可用。

H/L模式的切换步骤：

1. CPU阶段预先准备一组episode，GPU在深度模式下完成该组；组大小受磁盘、队列容量和等待时间限制，初值通过实测确定。
2. 深度进程结束、资源释放并验证后，启动本地Qwen；Astra与远端Qwen继续处理已有就绪数据。
3. 本地Qwen按组消费，不为每个事件重复加载。存在深度等待且达到配置的最长占用/等待预算时，停止给本地服务派发新请求，在当前不可中断请求完成后，于已保存回执的安全点交接；不能无限依赖等待整条结束。
4. 核验服务空闲和进程身份，只卸载本流水线拥有的服务。确认进程退出和显存释放后，再授予深度。跨请求图状态保存在磁盘，恢复时显式传入。
5. 若GPU被其他任务或非本流水线服务占用，进入外部资源等待并明确报告阻塞原因；不擅自终止、暂停或重配他人服务。不因远端故障自动回退到本地挤占GPU。

等待预算不包含强杀超时请求的授权；请求长期不返回时按服务超时/状态查询处理，保留所有权直到确认释放。调度必须避免深度长期饥饿，也避免每完成一条就切换造成反复加载。

GPU空闲、服务空闲和模型已卸载是三种不同状态。只判断nvidia-smi瞬时空闲显存，容易产生竞争；只判断HTTP没有请求，会漏掉常驻权重。两个条件与所有权互斥需一起检查。

#### 5.2.5 CPU、内存与磁盘的背压

CPU预处理起始沿用最多两路，GPU深度一路，本地Qwen至多一个请求；这些是起始上限，不是资源保证。根据可用内存、交换活动、CPU负载、解码/哈希磁盘开销调整任务领取，系统处于压力时先暂停新增任务，不丢弃已有证据。

内存判断使用available等有效指标，不能只凭free列；缓存与队列按字节及episode数双重限制。内存、磁盘和队列阈值在代表样本实测后固定并写入运行配置，不在未测量前编造容量。

### 5.3 状态与恢复

建议状态：已登记 → 审计通过 → 预处理通过 → 直接包就绪 → Astra通过 → 场景通过 → 事件通过 → 时序通过 → 最终验证通过。每阶段另有运行、等待、失败需诊断状态。

缓存键至少覆盖输入哈希、模型/服务版本、提示词、schema、参数，以及时序任务的前置图状态。前置状态改变时，其依赖的后续时序缓存失效。无关episode不应因此重跑。

请求超时保留请求身份和尝试证据；客户端不能把超时等同于服务端已经停止。可查询时先查询，支持幂等键时使用幂等键；否则明确记录潜在重复推理，避免无界重试。最终写入必须幂等。

仅重试失败阶段；通过的场景和事件不重复调用。输出格式失败与传输失败分别处理，有界重试后进入人工诊断队列。不得修改schema、伪造结果或更换模型身份来掩盖失败。

预处理协方差恢复继续按冻结策略：保留原阈值、排除坏样本、禁止跨坏样本插值，保留原始诊断和独立恢复输出。几何失效应显式保留，不为直接包“通过”而填充虚假TF。

## 6. 结果事实、空间树与时序约束

- 用户确认当前数据每条最后一次找到、此前均未找到。这是有作用域的人工事实，不是未来数据的普遍规则。当前已落地事实清单只枚举29条，不能据此宣称此前81条已修改。
- 该事实由确定性组装逻辑应用，并保留视觉原判断和人工来源。不能进一步推导精确找到帧、真实容器位置、没有重访或物体实例身份。
- 在线输入尚不知事件总数时，需要结束标记或已确认的事件清单，才能确定“最后一次”；不能每收到一次事件就称其最终找到。
- 树的节点ID跨事件稳定；无依据不能合并同名物体，也不能用事件局部ID断言不同物理区域。重访依赖同一物理区域的身份确认，无法确认时保持unknown。
- 每个有效时刻的已确定容纳/支承父关系遵循树契约，不成环、不产生冲突父节点；未定位节点按既有输出契约保留。
- 关系有效区间、采样窗口、证据时刻分开；三帧不能证明精确连续动作边界。晚期视图中发现的物体或容器状态不可无证据回填到早期。
- 参与者、搬移记录、测量数据等保留字段接口；没有真实来源不能由模型补造。

## 8. 验证与性能评估

### 8.1 正确性

- 输入覆盖：episode、目标、事件、左右三帧数量与清单一致，哈希及映射可复核；原有帧号偏差持续保留。
- 输出覆盖：原字段保留、潜在搜索区域存在，空间树和时序字段齐全；两个目标格式可导出。接口相同不代表生成值必然逐字相同。
- 关系质量：检查跨事件节点身份、容器开合与物体移动、关系起止、晚期证据泄漏、矛盾和重访判断。
- 证据约束：帧引用属于该事件，时间来源明确，不把无效几何当真值，不把人工结果确认扩展成位置确认。
- 故障恢复：模拟网络失败、输出截断、进程中断、重复领取和损坏文件，验证重试边界、单写和缓存失效。
- 资源互斥：覆盖本地Qwen已加载但无请求、深度等待、交接时仍有请求、资源租约超时、外部服务占用、卸载失败和突然退出；不能同时授予本地深度与本地Qwen。
- 资源容量：代表样本测量Qwen多图/长上下文及深度峰值，结合驱动与桌面留出实测余量；现有10,000 MiB深度门槛不下调。没有同卡并发峰值测试，不把单次成功视为支持长期并发。
- 压力与公平：两路CPU叠加网络打包、深度或本地Qwen时监测内存/交换/磁盘及GPU；有限批次内所有可处理任务最终推进，不能出现Qwen驻留使深度永久等待。
- 几何质量：独立报告VIO门槛；不能把最终JSON通过写成全部VIO通过。

### 8.2 计时

分别记录每阶段排队时间、实际执行时间、请求往返/重试、事件数量和图像/token预算；批次墙钟时间由批次起止计算，重叠任务不能相加冒充总时长。若扣除人为停机，单独记录并明确口径。

报告：单条端到端延迟、整批吞吐、两端负载差异、失败率与重试成本、磁盘用量、GPU/内存峰值、资源等待、模型加载/卸载次数与时间。Qwen仍可能是瓶颈；取消bag只节省对应I/O、序列化和提取开销，不能把深度/VIO时间都算成收益。R/H/L部署模式分别报告，不能用远端独立算力的结果承诺单GPU混合模式同等吞吐。

已有29条实际运行记录可作历史参考，但包含旧模型部署及实际重试；比较新架构应尽量固定输入、模型和请求配置。外部API模型变化需分开说明。

## 9. 合并S5与S6的独立实验边界

一次输入：事件三帧、目标、稳定节点表、前置有效空间状态及必要历史。一次输出：完整事件字段、关系变化提议、证据与不确定性。程序校验后才提交新图状态。

正常Qwen请求数由每条 `1+2N` 降为 `1+N`，不含Astra与重试；输出长度和单次推理负担会增加，不能据此推导耗时减半。

采用相同样本比较：描述细节遗漏、节点错配、关系错误、证据错误、格式失败/重试率和总耗时。若合并只减少请求却降低关键标注质量，不作为默认。S5/S6分开与合并必须有不同缓存键和版本标识。

## 10. 逐帧或分批流式的后续边界

运动筛帧算法具有因果处理属性，但现有外层VIO与筛帧程序仍按完整产物交接。真正逐帧需改造VIO输出、同步缓冲、坏样本隔离、阶段回执与恢复，不能只给现有脚本增加一个队列。

“凑够帧数”只是提交条件之一：还应考虑最大等待时间、视角互补、事件边界和尾批不足。局部Astra选择需保留候选并最终全局复核，避免早期视图冗余或漏掉后期容器内部；场景新增节点需要可追踪版本。

当前事件边界来自MD和三帧标记。仅有原始视频的新采集若要自动产生事件，需另外建设事件检测和边界确认能力，不属于第一版无bag接口改造。

## 11. 当前决策与实施前需核验的信息

已选方向：无bag直接包、保留缓存、以episode交接、一个Astra与两个Qwen、每条时序单写、保持最终JSON契约。暂不改变深度范围，不把S5/S6合并或逐帧筛选作为第一版前提。

实施前核验：三个API的访问配置与模型身份、两Qwen是否共享底层算力、本地部署是否属于这两个API、并发/速率/上下文/输出预算、是否支持当前结构化schema和多图输入、思考开关与缓存行为；选定R/H/L模式。密钥通过安全配置提供，不要求写入本文件。

本机结论已经明确：CPU预处理可与本地Qwen有限重叠，本地GPU深度与当前配置的本地Qwen默认互斥。如果两Qwen均为远端独立算力，优先R模式；本地Qwen不因“已经部署”而自动占用GPU。

这些信息影响客户端和资源参数，不妨碍先完成接口契约设计。涉及模型能力变化、取消深度或缺少三帧的新输入范围，应单独记录决定后再改对应阶段。
